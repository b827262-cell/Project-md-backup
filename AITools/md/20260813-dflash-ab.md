## 判定

**DFlash FAIL。** D arm startup 成功，但 correctness API 兩次均回：`The model produced output that does not match the expected peg-native format`（HTTP 500）。server log 可見 `common_chat_peg_parse: unparsed peg-native output`。因此沒有有效 D completion 可與 B 做 byte SHA 對照，也不得進入效能採用判定。錯誤證據未顯示 OOM、cudaMalloc、CUDA、RPC 或 kernel failure。

## 問題與風險

- 核心風險：DFlash 生成內容無法通過 Muse 的 peg-native parser；startup success 與高 acceptance 都不能消除此 correctness failure。
- D3 在未載入 drafter 時 free 3,154 MiB；D 啟動後 free 約 1,460 MiB，低於容量探索門檻 1,900 MiB。這是實測差值，不推論其他 ctx、split 或 workload 下的安全餘裕。
- TUF startup buffer-size 證據缺失，故無法以本輪資料量化遠端記憶體餘裕。
- 流程偏差：第一次 D correctness 呼叫將 `LOG` 錯寫成不存在的 `LOG_PATH`，量測器因未啟用 `set -e`，在 `stat` 報錯後仍送出請求並得到 HTTP 500；修正 log 參數後又執行一次，亦為 HTTP 500。故 D correctness 實際有兩次，而非一次。兩筆均保留，未挑選結果；確認失敗後即停止 D 效能測試並 rollback。
- B warm-up 與 R1 的 RX 數值明顯高於 R2/R3；計數器是整張介面增量，可能包含背景流量。此為**推論**，不影響 correctness gate，且本輪無 D 效能結果可比較。

## 結論

D3 能提供載入全本機 CUDA0 drafter 的啟動容量，DFlash 也能成功初始化並實際產生 draft acceptance；然而 D correctness 輸出未符合 peg-native format，API 兩次 HTTP 500。依 correctness-first 協定，不採用、不推薦 DFlash，不繼續優化、調參或效能測試。production 保持原 10-muse baseline。
